# 并查集原理

并查集把元素维护成若干互不相交的集合。每个集合是一棵树，树根是这一集合当前的代表元。初始每个元素自成一组，父节点指向自己。

## 合并与查询

- 查询时沿父指针找到根。根相同的两个元素同组。
- 合并时先找两个根。根不同时，将较小集合的根挂到较大集合的根下，并更新新根记录的集合大小。
- 查询到根后，把途经节点的父指针改为该根。这些节点的代表元仍是同一个根，所以路径压缩保持集合划分。

只用按大小合并时，一个节点每增加一层深度，它所在集合的大小至少翻倍，树高因此至多为 $O(\log n)$。再加上路径压缩，查询与合并的均摊时间为 $O(\alpha(n))$，其中 $\alpha$ 是反阿克曼函数。

## 适用条件

关系只增加时，可把每条无向边当作一次合并，在线查询连通性和连通分量大小。会删除边的题目需要根据操作顺序考虑离线处理、可撤销并查集或动态连通性算法。

## 常见疑问

**为什么合并两个根以后，还能用任意节点查集合大小？** `component_size(x)` 先找到 `x` 的当前根，再访问根维护的大小。合并后旧根的大小可能已过时。

**重复合并时计数会增加吗？** 如果两个元素已经同组，两次查询得到同一个根，合并就可以直接结束。
